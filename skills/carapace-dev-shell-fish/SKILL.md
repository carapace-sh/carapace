# Carapace Library: Fish Shell Integration Deep Dive

Reference for [carapace](https://github.com/carapace-sh/carapace)'s fish completion integration — how the snippet works, how completion output is formatted, and how carapace handles fish-specific edge cases.

## Source Files

| File | Purpose |
|------|---------|
| `internal/shell/fish/snippet.go` | Fish completion script generation |
| `internal/shell/fish/action.go` | Value formatting (tab-separated `value\tdescription`) |
| `internal/shell/shell.go` | Shared dispatch — message integration, nospace propagation, filtering |
| `complete.go` | Entry point — no fish-specific patching (unlike bash/nushell) |

## Fish Completion Background

### The `complete` Built-in

Fish registers completion functions via `complete -c command_name -f -a '(completion_function)'`. When the user presses TAB, fish:

1. Identifies the command being completed
2. Invokes the registered completion function (or command substitution in `-a`)
3. Parses the output as newline-separated candidates
4. Each line may contain a **tab character** — text before the tab is the completion value, text after is the description
5. Displays candidates in the pager with descriptions

### The `commandline` Built-in

The `commandline` built-in provides access to the current command line buffer. Key options used in carapace's snippet:

| Option | Meaning |
|--------|---------|
| `-c` / `--cut-at-cursor` | Print command line only up to cursor position |
| `-p` / `--current-process` | Limit to current process (stops at pipes, `&&`, `;`) |
| `-t` / `--current-token` | Select the current token being completed |
| `-x` / `--tokens-expanded` | Expand arguments, one per line (not used in carapace snippet) |

Combined `commandline -cp` returns the command line up to the cursor, limited to the current process — exactly what carapace needs for argument parsing.

### Fish `complete` Flags Used by Carapace

| Flag | Meaning |
|------|---------|
| `-c 'cmd'` | Register completion for command `cmd` |
| `-e` | Erase existing completion (prevents conflicts with built-in fish completions) |
| `-f` / `--no-files` | Disable file completion (carapace handles its own file suggestions) |
| `-a '(...)'` | Command substitution that produces completion candidates |
| `-r` / `--require-parameter` | Completion requires a parameter (offered after space) |

### Fish Completion Output Format

Fish expects completion output in a simple format:

```
value1\tdescription1
value2\tdescription2
value3\tdescription3
```

- Each line is one completion candidate
- Tab character (`\t`) separates the **value** (what gets inserted) from the **description** (what gets shown in the pager)
- If there is no tab, the entire line is the value with no description
- This is the **simplest format** among all carapace-supported shells

### Fish Word Splitting

Unlike bash, fish **does not split on `IFS` by default**. Fish splits command substitution output only on **newlines**, not spaces. This is a fundamental difference from bash's COMP_WORDBREAKS problem — fish never splits `origin/main` at `:` or `--option=value` at `=`.

Fish also does not have bash's concept of COMP_WORDBREAKS at all. The command line tokenizer properly handles `:`, `=`, `@`, and other characters that cause issues in bash.
## The Fish Snippet

Generated by `fish.Snippet(cmd)` in `internal/shell/fish/snippet.go`:

```fish
function _example_completion
  set --local data
  IFS='' set data (echo (commandline -cp)'' | sed "s/ $/ ''/" | xargs example _carapace fish 2>/dev/null)
  if [ $status -eq 1 ]
    IFS='' set data (echo (commandline -cp)"'" | sed "s/ $/ ''/" | xargs example _carapace fish 2>/dev/null)
    if [ $status -eq 1 ]
      IFS='' set data (echo (commandline -cp)'"' | sed "s/ $/ ''/" | xargs example _carapace fish 2>/dev/null)
    end
  end
  echo $data
end

complete -e 'example'
complete -c 'example' -f -a '(_example_completion)' -r
```

### Snippet Walkthrough

**1. Define the completion function**

```fish
function _example_completion
  set --local data
```

A local variable `data` holds the completion output.

**2. Open-quote retry logic**

The three-stage retry handles the **open-quote problem**:

```fish
IFS='' set data (echo (commandline -cp)'' | sed "s/ $/ ''/" | xargs example _carapace fish 2>/dev/null)
if [ $status -eq 1 ]
  IFS='' set data (echo (commandline -cp)"'" | sed "s/ $/ ''/" | xargs example _carapace fish 2>/dev/null)
  if [ $status -eq 1 ]
    IFS='' set data (echo (commandline -cp)'"' | sed "s/ $/ ''/" | xargs example _carapace fish 2>/dev/null)
  end
end
```

**Why this is needed**: When the user types `example --flag "partial_wor⇥`, fish's `commandline -cp` returns the line including the opening double quote. But `xargs` (used to split the line into arguments) fails with exit status 1 if there's an unmatched quote. The retry logic progressively tries to close the quote:

1. `''` — append two single quotes. Handles the normal case (no open quote) and the case where the user has an open single quote like `'partial`. The `''` is an empty single-quoted string in fish, effectively closing any open single quote.
2. `"'"` — append a single quote inside double quotes. Handles the case where the user typed `'partial` (open single quote). The `"'"` closes the single quote.
3. `'"'` — append a double quote inside single quotes. Handles the case where the user typed `"partial` (open double quote). The `'"'` closes the double quote.

Each attempt pipes through `sed "s/ $/ ''/"` which appends `''` to lines ending with a space (handling the edge case of a trailing space that would cause `xargs` to misbehave), then through `xargs` to split into arguments.

**3. Output the data**

```fish
echo $data
```

The completion data (tab-separated `value\tdescription` lines) is printed to stdout. Fish captures this via the command substitution in the `-a` flag.

**4. Register the completion**

```fish
complete -e 'example'
complete -c 'example' -f -a '(_example_completion)' -r
```

- `complete -e` erases any existing completion for the command — critical to prevent fish's built-in completions from interfering
- `-f` / `--no-files` disables fish's default file completion — carapace provides its own file suggestions
- `-a '(_example_completion)'` — the function is invoked as a command substitution; its stdout is parsed as completion candidates
- `-r` / `--require-parameter` — tells fish that a parameter is required after the command name (enables completion after space)

For a cross-shell comparison of snippet design, see the **carapace-dev-shell** skill.

## Value Formatting: `ActionRawValues()`

`fish.ActionRawValues(currentWord, meta, values)` in `internal/shell/fish/action.go` is the simplest formatter in carapace — only 6 lines of logic.

### Implementation

```go
var sanitizer = strings.NewReplacer(
    "\n", ``,
    "\r", ``,
    "\t", ``,
)

func ActionRawValues(currentWord string, meta common.Meta, values common.RawValues) string {
    vals := make([]string, len(values))
    for index, val := range values {
        vals[index] = fmt.Sprintf("%v\t%v", sanitizer.Replace(val.Value), sanitizer.Replace(val.TrimmedDescription()))
    }
    return strings.Join(vals, "\n")
}
```

### Step 1: Sanitize

The sanitizer strips control characters that would break the output format:

- `\n` → empty — newlines are the record delimiter; a value containing a newline would create spurious candidates
- `\r` → empty — carriage returns would corrupt the output
- `\t` → empty — tabs are the field delimiter (value vs description); a value containing a tab would split the value and shift the description

### Step 2: Format as Tab-Separated

Each `RawValue` becomes `value\tdescription`. The `Value` field is what gets inserted; `TrimmedDescription()` is what shows in the pager. Empty descriptions produce `value\t` (a trailing tab with empty description text), which fish displays as the value with no description.

### Step 3: Join with Newlines

All candidates are joined with `\n`. Fish splits on newlines to get individual candidates.

## No Fish-Side Patching

Unlike bash and nushell, **fish has no `Patch()` function**. The `complete.go` dispatch has no `case "fish"` branch — fish arguments are passed directly to `traverse()` unmodified.

This is because fish does not suffer from the problems that require patching in other shells (see the **carapace-dev-shell** skill for a cross-shell comparison of patching needs).

Fish's tokenizer (using the `TOK_ACCEPT_UNFINISHED` flag) is designed for completion — it can handle partially typed, syntactically invalid command lines. The `commandline -cp` output is already a clean representation of the command line up to the cursor, without the redirect-leaking or word-splitting problems that bash has.

The open-quote problem is still present but is handled entirely in the snippet (the 3-stage xargs retry), not in Go-side patching.

## Nospace Handling: A Known Limitation

### The Problem

Carapace's `SuffixMatcher` (accessed via `meta.Nospace`) controls whether a trailing space should be added after a completion. Many shells support this:

- **bash**: `compopt -o nospace` (global — applies to ALL candidates)
- **zsh**: `CodeSuffix` per candidate (empty string = no space)
- **elvish**: `CodeSuffix` per candidate (empty string = no space)
- **nushell**: Omits trailing space in JSON output per candidate
- **powershell**: Strips trailing space from `CompletionText` per candidate

**Fish's `ActionRawValues` ignores `meta.Nospace` entirely.** The function receives `meta` as a parameter but never references `meta.Nospace`. There is no mechanism in the tab-separated format to communicate nospace information.

### Why This Matters

Without nospace support, completing values that end with delimiters like `:`, `/`, `=`, `@`, or `,` will have an unwanted trailing space. For example:

```
User types: git remote add origin<TAB>
Completion: origin    (from ActionValues("origin", "upstream"))
Result:     git remote add origin ⇥   →  "origin " (trailing space added)
```

With nospace (e.g., `NoSpace('/')` on directory completions), the user could continue typing after the directory without backspacing. Without it, the space must be removed manually.

### Fish's Built-in Nospace

Fish's `CompleteFlags::NO_SPACE` flag does exist in fish's Rust internals, but it's only accessible through:

- The `-x` / `--exclusive` flag on `complete` (which combines `-r` and `-f`)
- The `NO_SPACE` flag on individual completions generated by fish's internal completion system

Carapace's external command substitution approach (`-a '(_completion)'`) cannot set per-candidate nospace flags. The completion function's stdout is parsed as plain `value\tdescription` text — there is no way to communicate the NO_SPACE flag through this interface.

### What shell.go Does (Dead Code for Fish)

In `shell.go`, the shared dispatch adds `*` to the nospace set when messages exist:

```go
if shell != "export" {
    switch {
    case !meta.Messages.IsEmpty():
        meta.Nospace.Add('*')    // messages ⇒ force nospace on ALL values
    case env.Nospace() != "":
        meta.Nospace.Add([]rune(env.Nospace())...)  // CARAPACE_NOSPACE env var
    }
}
```

This sets `meta.Nospace.Add('*')` when messages exist, but since **fish's `ActionRawValues` never reads `meta.Nospace`**, this has **no effect** for fish completions. It is effectively dead code for the fish path.

### Possible Workaround

One approach would be to append a special marker character (like bash's `\001` or oil's nospace indicator) that the snippet function could parse and translate into fish's `--exclusive` option. However, this would require a more complex snippet that processes each candidate individually rather than using a simple command substitution.

### Current Behavior

Since fish's formatter ignores nospace, **every completion in fish gets a trailing space**. This matches fish's default behavior for most completions but is wrong for values where nospace was explicitly requested (like directories ending in `/`, or comma-separated values ending in `,`).

## Message Handling

Fish falls into the **`default`** case in `shell.go`'s message handling:

```go
switch shell {
case "elvish", "export", "zsh": // shells with support for showing messages
default:
    values = meta.Messages.Integrate(values, value)
}
```

This means messages are **integrated as synthetic completion candidates** via `meta.Messages.Integrate(values, value)`. This method (in `internal/common/message.go`) converts messages into fake completion values:

- Display text: `ERR`, `ERR1`, `ERR2`, etc. (incrementing to avoid collisions with real values)
- Value text: `<currentWord prefix>ERR`, `<currentWord prefix>ERR1`, etc.
- Description: the actual error message text
- Style: `style.Carapace.Error`

When only one message exists and no other candidates, an additional `_` placeholder value is added to prevent fish from auto-inserting the error message.

For a cross-shell comparison of message handling, see the **carapace-dev-shell** skill.

## Description Display and the Fish Pager

### How Fish Shows Descriptions

When a completion candidate includes a tab character, fish splits on that tab. The first part becomes the **completion value** (what gets inserted), and the second part becomes the **description** (shown in the pager next to the value).

Fish's pager displays descriptions in a column to the right of the values. The pager:

- Automatically calculates column widths based on terminal size
- Shows descriptions in a dimmer color by default
- Supports fuzzy matching when the user types to filter candidates
- Groups candidates with the same description into a single entry

### Carapace's Description Truncation

Carapace uses `val.TrimmedDescription()` rather than `val.Description` in the fish formatter. The `TrimmedDescription()` method truncates descriptions that exceed `CARAPACE_DESCRIPTION_LENGTH` (default 80 characters), adding an ellipsis for long descriptions. This prevents the fish pager from becoming unreadable with overly long descriptions.

### Style Support

Fish's formatter does **not** output any style information. The `val.Style` field from `RawValue` is completely ignored. This is consistent with fish's completion format — there is no standard way to embed color/style information in `value\tdescription` output.

Fish does have pager color customization via `fish_pager_color_*` variables, but these apply globally to all completions, not per-candidate.

## Edge Cases and Known Issues

### 1. Open-Quote Completion

The most significant edge case. When the user is inside an unclosed quote:

```
example --flag "partial_wor⇥
```

Fish's `commandline -cp` returns the entire line including the opening quote. The snippet's 3-stage retry handles this by progressively closing the quote before passing to `xargs`.

**Limitation**: The retry logic is a heuristic. It covers the three most common cases (no open quote, open single quote, open double quote) but may fail for:

- Nested quotes: `example --flag "it's a 'test⇥`
- Mixed quote scenarios: `example --flag 'mixed "quote⇥`
- Escaped quotes: `example --flag "with \"inside⇥`

In practice, these cases are rare and the fallback behavior (no completions shown) is acceptable.

### 2. Trailing Spaces in Arguments

The `sed "s/ $/ ''/"` command in the snippet handles the edge case where `commandline -cp` returns a line ending with a space (indicating the cursor is after a space and the user is completing a new argument). Without this fix, `xargs` would interpret the trailing space differently.

The fix appends `''` (empty single-quoted string) to lines ending with a space, ensuring `xargs` processes the arguments correctly.

### 3. Fish Doesn't Properly Erase Completions (fish-shell#6716)

The `complete -e 'cmd'` in the snippet is meant to erase any existing fish completions for the command. However, there's a known fish issue ([fish-shell#6716](https://github.com/fish-shell/fish-shell/issues/6716)) where `complete -e` may not properly erase completions in all cases.

The workaround used by carapace-bin is to create an **empty stub file** at `~/.config/fish/completions/{cmd}.fish` — this prevents fish from loading its own built-in completions for that command, since fish's autoloading prefers user-defined completions.

### 4. Special Characters in Values

Fish interprets certain characters as special syntax: `()`, `$`, `{}`, `<>`, `*`, `?`, `[`, `]`, and others. When completion values contain these characters, fish's completion system may:

- In older fish versions: escape them with backslash (`\[test\]`)
- In newer fish versions (4.0+): quote them (`'[test] file1'`)

This can cause inconsistent behavior depending on the fish version. Carapace's fish formatter does **not** perform any shell-specific escaping of special characters in completion values — it relies on fish's built-in escaping when displaying candidates.

### 5. No Per-Candidate Nospace

As detailed in the Nospace Handling section, fish's tab-separated format has no way to communicate per-candidate nospace information. This means:

- Directory completions ending in `/` get an unwanted trailing space
- Colon-separated values (like `origin/main`) get a trailing space even when `NoSpace(':')` is requested
- Comma-separated values (like `first,second,`) get a trailing space even when `NoSpace(',')` is requested

### 6. No Style/Color Support

The fish formatter ignores all style information from `RawValue.Style`. Fish's `value\tdescription` format has no mechanism for per-candidate colors. Fish does support pager color customization via `fish_pager_color_*` environment variables, but these apply globally.

### 7. `IFS=''` in the Snippet

The `IFS=''` before `set data` is critical. Without it, fish would split the completion output on whitespace, destroying values that contain spaces. By setting `IFS` to empty, the entire output is captured as a single string, preserving spaces in values and descriptions.

### 8. Integration Tests Are Commented Out

In `example/main_test.go`, the fish integration tests are entirely commented out:


## Completion Dispatch Flow for Fish

```
User presses TAB
  → Fish invokes _cmd_completion function
  → Snippet: commandline -cp gets command line up to cursor
  → Snippet: 3-stage open-quote retry with xargs
  → carapace _carapace fish subcommand receives args
  → complete() in complete.go detects shell
  → NO fish-specific patching (no case "fish" in switch)
  → traverse(cmd, args[2:]) → resolve action + context
  → action.Invoke(context) → InvokedAction
  → InvokedAction.value("fish", currentWord)
  → shell.Value() applies global preprocessing:
      1. Color disable if NO_COLOR
      2. Prefix filtering (unless CARAPACE_UNFILTERED)
      3. Message integration (ERR values for fish)
      4. Nospace propagation (dead code for fish — ignored by formatter)
      5. Sort + dedup + clear UIDs
  → fish.ActionRawValues(currentWord, meta, values):
      1. Sanitize values (strip \n, \r, \t)
      2. Format as "value\tdescription" per line
      3. Join with \n
  → Snippet: echo $data
  → Fish parses tab-separated output, displays in pager
```
